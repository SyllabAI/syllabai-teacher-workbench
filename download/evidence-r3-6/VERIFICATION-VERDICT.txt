Date (UTC): 2026-09-13

1. OBJECTIVE
   Make it visually and semantically impossible to confuse:
     (a) CANONICAL state — what is actually persisted in the canonical DB,
     (b) STAGED intent  — what a teacher proposed in the workbench (never truth),
     (c) APPLIED events — what the gated importer committed, with attribution.

2. WHAT SHIPPED (workbench app, commit 2f6e8a7 local main)
   - TargetStatePanel on every review target (paper / question version /
     mark scheme): separate CANONICAL row (badge + "live DB" chip + target
     identity + last applied event), STAGED rows (one per staged entry with
     explicit "STAGED — NOT YET APPLIED" or closed-state chips), APPLIED rows
     (event ledger with reviewer + time + seq/hash), and a relationship badge
     per staged intent with a full-sentence explanation.
   - Relationship semantics in a PURE module (src/lib/canonical-relationship.ts)
     shared by UI and tests: AGREES_WITH_CANONICAL / WOULD_CHANGE_CANONICAL /
     ALREADY_APPLIED / APPLIED_THEN_REVERSED / BLOCKED — deliberately NOT
     collapsed into one status field.
   - Live canonical feed: GET /api/canonical/events (applied events with
     attribution) + POST /api/canonical/state (live validation_state per
     target, UNKNOWN for stale/malformed ids). Both READ-ONLY, fail-closed.
   - Authorization boundary (genuine contract extension, mandated by gate 10):
     POST /api/session issues an HMAC-signed HttpOnly teacher-session cookie;
     staging POST now returns 403 without a valid teacher session. GETs and
     payload shapes unchanged (backward compatible).
   - Connection-level read-only enforcement: the workbench's canonical DB
     pool opens with default_transaction_read_only=on — the serving path is
     PHYSICALLY unable to mutate canonical state even through a code bug.
   - Stale provenance fixed: header now shows core 9615b69 (was a54f310),
     read-model label DERIVED-FROM-CANONICAL (was INFERRED), footer states
     canonical DB LIVE (was "pending repo access").
   - Test-isolation hook: TV_LOG_FILE env override so tests never touch the
     real hash-chained staging log.
