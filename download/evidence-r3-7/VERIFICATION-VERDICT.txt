2. WHAT SHIPPED (workbench repo)
   - Reviewer registry + provisioning CLI (scripts/provision-reviewer.ts):
     one token per reviewer, shown once, stored ONLY as sha256; unique
     active names (no shared accounts); append-only provisioning audit log;
     revocation bumps epoch (immediate session death); rotation command.
   - Sessions v2: payload binds {reviewerId, name (registry-authoritative),
     role, exp, epoch}. Issuance REQUIRES a provisioned token. Staging
     revalidates the registry on EVERY write. Legacy v1 cookies fail closed.
   - Cookie: HttpOnly, SameSite=Strict, Secure in production.
   - Production fail-closed gate (src/instrumentation.ts): missing/undersized
     secret, missing registry, TV_PUBLIC_HTTPS!=1, or implicit DB defaults ->
     explicit startup failure (prod-boot-check.log: all six problems listed;
     insecure boot fails to prepare; secure boot serves 200).
   - Live canonical staging gate (mirror of the importer, which remains the
     sole apply authority): VALIDATE/REJECT/FLAG require LIVE SUGGESTED
     (fail-closed on feed unavailability); REVERSE requires the prior entry
     applied AND still the last event on the target. A stale read model can
     no longer admit intent against a target whose canonical state moved.
   - CSRF hardening: application/json required; cross-origin Origin refused.
   - Relationship semantics (pure module, five R3-6 kinds preserved): open
     state-changing intent vs non-SUGGESTED canonical = BLOCKED with an
     explicit CONFLICT explanation; STALE flag + supersededBy[] carrying the
     newer applied events' attribution. Never collapsed into one status.
   - reviewerId rides in staging entries OUTSIDE the frozen hash base
     (F-3 pattern) — cross-side compatibility PROVEN: bun helper reproduces
     real-log hashes; importer check-mode accepts reviewerId-bearing logs.
   - Repo hygiene: *.tar.gz/*.dump* + identity-state gitignore rules,
     pre-commit hook, check-large-files.sh, docs/RELEASING.md.
